# Unity 3D场景设计需求文档

> ⚠️ **本文档已废弃（v1 单路设计）**。当前 3 路灌溉版本的场景设计请见
> `frontend-unity/Unity场景设计文档.md`，数据接口见 `docs/系统接口契约v3.md`。

## 🎯 总体设计目标

创建一个直观、交互友好的**数字孪生灌溉系统**3D可视化界面，实现：
- 实时环境数据监控
- 智能灌溉过程可视化
- 历史数据趋势分析
- 预测数据显示
- 手动/自动灌溉控制

## 🏗️ 场景元素设计

### **1. 温室主体结构**
```
✅ 必需元素：
- 透明玻璃墙体和屋顶
- 支撑柱结构
- 通风口/窗户
- 入口门

📐 设计参数：
- 尺寸：10m × 8m × 4m（长×宽×高）
- 风格：现代化智能温室
- 材质：玻璃反光效果 + 金属框架
```

### **2. 灌溉设备模型**
```
💧 主要设备：
- 喷头/滴灌装置（根据灌溉类型选择）
- 主水管管道系统
- 水泵设备房（半透明可看到内部）
- 控制阀门
- 水箱/蓄水池

🎨 视觉效果：
- 管道：PVC材质，灰色或白色
- 水泵：运行时要有LED指示灯
- 喷头：灌溉时显示水流粒子效果
- 水流：蓝色透明粒子系统，真实流动感
```

### **3. 作物种植区域**
```
🌱 作物区域：
- 种植床：4个矩形种植区域（2×2布局）
- 作物模型：使用生菜/小白菜等叶菜类3D模型
- 生长阶段显示：幼苗期、生长期、成熟期
- 土壤可视化：不同湿度显示不同颜色和纹理

🎨 湿度可视化效果：
- >60%：深棕色，湿润效果
- 30-60%：棕黄色，正常状态  
- <30%：浅黄色偏白，干燥效果
- 灌溉中：显示水滴反光效果
```

### **4. 环境监控设备**
```
📡 传感器模型：
- 土壤湿度传感器（插入土壤中的探针）
- 温湿度传感器（悬挂在空中）
- 数据采集点（小型Arduino/ESP32模型）

📊 数据显示：
- 传感器上方显示实时数值
- 设备状态指示灯（绿色正常、红色异常）
- 数据传输动画效果（WiFi图标或传输波纹）
```

## 🎮 交互功能设计

### **1. 主要交互界面**
```
🖱️ 鼠标控制：
- 左键拖拽：旋转相机视角
- 右键拖拽：平移场景
- 滚轮：缩放视角
- 点击物体：查看详细信息/进入控制模式

📱 触摸屏支持（可选）：
- 单指拖拽：旋转场景
- 双指缩放：调整视距
- 双指点击：选择对象
```

### **2. 控制面板功能**
```
📲 UI面板布局：
左上角：实时数据显示面板
右上角：系统状态监控面板  
右侧：预测数据图表面板
底部：灌溉控制按钮面板
左侧：历史数据选择器

⚡ 实时数据面板：
- 土壤湿度：进度条 + 数值显示
- 环境温度：温度计图标 + 数值
- 空气湿度：水滴图标 + 百分比
- 水泵状态：运行指示灯 + 运行时间

📈 预测数据面板：
- 30分钟/1小时/2小时预测切换
- 折线图显示湿度趋势
- 当前值vs预测值对比
- 预测置信度显示
```

### **3. 灌溉控制功能**
```
🎛️ 控制模式：
- 自动模式：系统根据湿度阈值自动控制（比赛要求的核心功能）
- 手动模式：用户手动控制启停
- 定时模式：设置定时灌溉计划

🎮 控制操作：
- "启动灌溉"按钮：立即开始灌溉
- "停止灌溉"按钮：立即停止灌溉
- "持续时间"滑块：1-30分钟可选
- "灌溉阈值"设置：湿度低于多少时自动触发
- "单次灌溉量"调节：控制灌溉时长

📱 移动端适配：
- 按钮大小适合触摸操作
- 面板可折叠/展开
- 支持横屏和竖屏布局
```

## 🎨 UI/UX设计要求

### **1. 设计风格**
```
🎨 视觉风格：
- 整体色调：科技蓝 + 生态绿
- 界面风格：现代化、简洁、科技感
- 字体：无衬线字体，清晰易读
- 图标：扁平化设计，语义明确

✨ 特效要求：
- 数据更新时平滑过渡动画
- 灌溉触发时的视觉提醒波纹效果
- 警告状态时的闪烁提醒（湿度过低时）
- 水流粒子效果要逼真
```

### **2. 数据可视化设计**
```
📊 图表类型：
- 土壤湿度趋势图：线形图，显示24小时历史
- 温度变化图：面积图，带昼夜背景区分
- 预测数据对比图：双轴线图（实际+预测）
- 灌溉统计饼图：手动vs自动灌溉占比

🎨 颜色方案：
- 土壤湿度：深蓝 → 浅蓝 → 橙色 → 红色（高→低）
- 温度：蓝色（冷）→ 绿色（适）→ 红色（热）
- 水泵状态：灰色（停止）→ 蓝色闪烁（运行）
- 警告状态：黄色（注意）→ 红色（紧急）
```

### **3. 用户体验优化**
```
🚀 性能要求：
- 场景加载时间 < 3秒
- 数据刷新频率：每5秒一次
- 3D渲染帧率：稳定30FPS以上
- 内存占用：<500MB

🎯 交互优化：
- 防误操作确认：重要操作需要二次确认
- 操作反馈：每次操作都有成功/失败的视觉反馈
- 状态指示：清晰的颜色编码和图标系统
- 错误处理：网络中断时的重连机制和提示

📱 响应式设计：
- 支持不同屏幕分辨率自适应
- 移动端：简化界面，突出核心功能
- PC端：完整功能面板，支持键盘快捷键
```

## 🔧 技术实现要求

### **1. Unity技术栈**
```
🛠️ 推荐使用：
- Unity版本：2021.3.10或更高版本
- 渲染管线：URP（通用渲染管线）- 提升性能
- UI系统：Unity UI + TextMeshPro
- 网络通信：UnityWebRequest
- 数据图表：使用Unity插件（如XCharts）
- 3D模型资源：使用Asset Store免费资源或自定义建模

📦 必要插件：
- Newtonsoft.Json：用于JSON数据处理
- TextMeshPro：高质量文本渲染
- XCharts或类似图表库：数据可视化
```

### **2. 网络通信架构**
```
🌐 通信层设计：
- 基于HTTP RESTful API通信
- 使用UnityWebRequest进行网络请求
- 实现错误重连机制（最多3次重试）
- 数据缓存策略：网络中断时显示最后有效数据

⚡ 性能优化：
- 请求频率控制：实时数据5秒刷新一次
- 历史数据分页加载：避免一次性加载过多
- 图表数据点限制：最多显示100个数据点
- 异步加载：避免UI卡顿
```

### **3. 数据同步机制**
```
🔄 数据同步逻辑：
1. 启动时先获取系统状态（/api/system-status）
2. 启动定时器每5秒获取实时数据
3. 用户查看历史数据时按需请求
4. 预测数据每30秒更新一次
5. 控制命令实时发送，立即更新UI

❌ 异常处理：
- 网络超时：显示"连接中..."，3秒后重试
- 服务器无响应：显示"服务器离线"，使用本地缓存数据
- 数据格式错误：记录日志并显示"数据异常"
- 控制失败：弹出错误提示，提供重试按钮
```

## 💻 开发环境配置

### **1. 开发环境要求**
```
🔧 硬件要求：
- CPU：Intel i5/i7 或 AMD同等性能
- 内存：8GB以上（推荐16GB）
- 显卡：支持DirectX 11，GTX 1060或更高
- 存储：至少5GB可用空间

📦 软件依赖：
- Unity Hub 2.4.5+
- Unity Editor 2021.3.10或更高版本
- Visual Studio Code / Visual Studio 2019
- Git（版本控制，可选）
```

### **2. 项目创建步骤**
```
1. 创建新Unity项目
2. 导入必要Package：
   - Universal RP (URP)
   - TextMeshPro
   - Input System
3. 配置项目设置：
   - 切换到URP渲染管线
   - 设置目标平台：Windows/Mac/Linux + WebGL
   - 配置Player Settings
4. 创建项目文件夹结构：
   ```
   Assets/
   ├── Scenes/              # 场景文件
   ├── Scripts/             # C#脚本
   ├── Models/              # 3D模型
   ├── Materials/           # 材质文件
   ├── Textures/            # 贴图资源
   ├── Prefabs/             # 预制体
   ├── UI/                  # UI界面
   └── Shaders/             # 自定义着色器
   ```

### **3. 联调测试流程**
```
🧪 测试步骤：
1. 启动Python模拟数据服务器
2. 在Unity中使用编辑器模式测试API连接
3. 验证实时数据更新是否正常
4. 测试灌溉控制功能
5. 验证历史数据查询
6. 测试预测数据展示
7. 全功能集成测试
8. 性能压力测试

📋 测试检查清单：

- [ ] 网络异常时有正确提示
