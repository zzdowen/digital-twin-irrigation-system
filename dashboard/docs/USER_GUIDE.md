## 2. 登录

| 项 | 说明 |
| --- | --- |
| 用户名 | 由管理员分配，初始管理员是 `admin` |
| 密码 | 至少 8 位 |
| 登录状态 | 保持 12 小时，过期需重新登录 |

### 首次登录必须改密码

用初始密码第一次登录时，看板会**强制弹改密界面**，改完才能进主界面。

这是安全设计：初始密码是安装时随机生成的、写在服务器文件里的，
必须换成只有你自己知道的密码。

### 密码输错 5 次会锁 10 分钟

同一个账号连续输错 5 次，会被锁 10 分钟。等待即可，不用找人解锁。

### 忘记密码

找管理员在「账号」页给你重置；管理员自己忘了就看 `DEPLOY.md` 第 11.6 节。

## 4. 界面导览

登录后是单页应用，顶部一排标签切换，**不会整页刷新**：

```
[总览] [趋势] [预测] [事件] [天气] [告警] [控制] [账号]
```

下面逐个说。

---

### 4.1 总览（默认页）

一眼看清当前状态。

**三张通道卡片**，每张显示：

- **大号含水量数字**（百分比，1 位小数）
- **状态色**：正常 = 蓝/绿，偏干 = 橙，过湿 = 紫，离线 = 灰
- **泵状态**：运行中 / 已停止
- **环形进度**：含水量的可视化圆环

卡片上方还有：

| 指标 | 含义 |
| --- | --- |
| 平均含水量 | 三个通道的平均值 |
| 活跃泵数 | 当前有几个泵在转（0~3） |
| 数据新鲜度徽章 | 数据多久没更新了；**超过 10 分钟会变红并显示「数据已过期」** |
| 告警徽章数字 | 当前有几条未恢复的告警 |
| 累计时长 | 见下面「累计时长是怎么算的」，是个会走的计时器 |
| 灌溉次数 / 用水量 | 已完成的灌溉事件条数与估算用水量（升） |

#### 累计时长是怎么算的

显示成 `xx 天 xx 小时 xx 分 xx 秒`，在跑泵的时候**每秒跳一格**。

它由两段相加得来：

```
累计时长 = 已完成时长（上游事件表里所有灌溉时长之和）
         + 本次已运行时长（正在转的泵，从开始转到现在）
```

**这个数字是「只算已经证实过的时间」**，所以它不会骗你：

| 情况 | 计时器的行为 |
| --- | --- |
| 一切正常、泵在转 | 每秒 +1，旁边的「计时中」小标签在闪 |
| 泵停 | 本次归零，已跑的那段立刻并进「已完成」（数字不倒退） |
| 网络断了 / 上游服务挂了 | **10 秒内停表**，数字冻结不动，下方出现橙字说明原因 |
| 断流恢复了 | 从冻结的那个数**原地继续**，**不会把断掉那几分钟补回去** |
| 服务器重启 | 5 分钟内重启，已证实的秒数会接着算；超过 5 分钟就从 0 重新起算 |

> **为什么断流不补？**
> 因为那段时间我们**没有观测到**泵到底转没转。宁可少算，也不凭空多算。
> 你看到 `读数已 46 秒未更新，计时已暂停` 这类橙字，就是它在告诉你「这段时间我没看见」。

**状态判定规则**（这三个阈值是固定的）：

| 状态 | 条件 | 颜色 |
| --- | --- | --- |
| 正常 | 30% ≤ 含水量 ≤ 95% | 蓝/绿 |
| 偏干 `dry` | 含水量 < 30% | 橙 |
| 过湿 `wet` | 含水量 > 95% | 紫 |
| 离线 `offline` | 超过 600 秒（10 分钟）没有新数据 | 灰 |

> **看到徽章变红「数据已过期」怎么办？**
> 先刷新页面。还是红的，说明上游采集停了——联系技术同事，
> 不是你的操作问题，也别自己去重启服务器上的服务。

### 4.2 趋势

看历史曲线，判断变化趋势。

- **时间范围切换**：1 小时 / 6 小时 / 24 小时 / 72 小时 / 7 天
- **三条折线**：三个通道叠在同一张图上，颜色区分
- **泵状态阶梯带**：曲线下方的一条带子，显示每个时刻泵是开还是关
- **鼠标悬停**：显示该时刻的具体数值
- **「导出 CSV」按钮**：把当前时间范围的历史数据下载成表格文件

**导出的 CSV 直接用 Excel 打开不会乱码**（文件带 UTF-8 BOM）。

> 曲线在长时间段会做「降采样」——把很多点按时间桶平均成较少的点，
> 这样图不会卡。所以 7 天视图的曲线比 1 小时视图平滑，这是正常的。

---

### 4.3 预测

未来含水量的预测曲线。

- **预测时长切换**：未来 30 / 60 / 120 分钟
- 预测曲线会与**最近一段实测曲线拼接**显示，方便对比
- 图下方标注了**算法名称和精度**（各通道的平均绝对误差百分比，越小越准）

> **精度是什么**：上游用「加权线性回归 + 指数平滑 + 天气感知」外推，
> 精度列是它历史的**平均绝对误差（MAE）百分比**。当前实测三块地都在
> **5%~7%** 之间（实测 5.8% / 6.8% / 5.4%，会随时间略有浮动），
> 意味着 30 分钟后的预测值大约有 ±6% 的偏差。
>
> 如果某段时间显示 `0.0%`，那是上游当时还没攒够可比对的历史点，
> 不代表预测没用；看板照实显示，**不会编一个好看的假数字**。

> 如果显示「上游预测格式未识别」，说明上游改了数据格式，
> 看板会返回空预测而不是报错——联系技术同事即可。

### 4.4 事件

历史上每一次灌溉的记录。

- **事件表格**：开始时间、通道、持续时长
- **按天汇总柱状图**：每天灌溉了几次、总共多少分钟
- 默认看最近 30 天

> **表格是空的？** 先看页面底部是不是提示「上游历史库不可读」。
> - **没有这个提示、只是表格空**：就是这段时间确实没灌过水，属正常。
> - **有这个提示**：是部署权限没配好（`farm` 账号读不到上游的历史库），
>   找管理员按 `DEPLOY.md` 第 11.4 节补一次授权即可，其余功能不受影响。

### 4.6 告警

系统自动判断出来的异常，列表展示。

**告警级别**（按严重程度）：

| 级别 | 颜色 | 含义 |
| --- | --- | --- |
| critical | 红 | 严重，立刻处理（如上游断连、数据中断） |
| warning | 橙 | 需要关注（如偏干、长时间连续灌溉） |
| info | 蓝 | 提示性质（如过湿） |

**五条告警规则**：

| 规则 | 触发条件 | 级别 | 给人看的话 |
| --- | --- | --- | --- |
| `dry` | 任一通道含水量 **< 30%** | warning | 「1 号地块含水量 22.4%，低于 30%，建议灌溉」 |
| `wet` | 任一通道含水量 **> 95% 且持续 ≥ 3 次采样** | info | 提醒可能浇水过多 |
| `long_irrigation` | 同一通道**连续开泵 ≥ 60 分钟** | warning | 提醒可能卡住了 / 忘了关 |
| `no_data` | **超过 600 秒**没有新数据 | critical | 数据采集中断 |
| `upstream_down` | 连续 **3 次**采样都连不上上游 | critical | 上游灌溉服务离线 |

**未恢复的告警会置顶显示。**

> 同一个通道的同一种问题**不会重复刷屏**——在恢复之前只更新最后发生时间，
> 不会每分钟新增一条。

### 4.7 控制（仅操作员 / 管理员可见）

手动开泵、停泵。

**操作步骤：**

1. 选通道（1 / 2 / 3）
2. 填时长（分钟）
3. 点「开始」或「停止」
4. **会弹二次确认框**——确认后才真正下发
5. 操作后右上角弹提示，总览数据自动刷新

> 所有控制操作都会记进**审计日志**（谁、什么时候、对哪个通道、做了什么、结果如何），
> 且会原样转发给上游灌溉服务执行。
>
> 如果提示「灌溉服务暂时不可达」，说明上游没响应，操作**没有生效**，稍后重试。

## 5. 三通道读数为什么各不相同、还会上下浮动

**现在的画面**：三块地的含水量各在一个区间里缓慢变化（比如 44.0% / 41.3% / 47.0%），
泵会在含水量跌到触发点时自动打开，浇到目标值自动停。这是**正常的、也是真实模拟**。

### 5.1 它按什么在算

土壤含水量的变化遵循农田的**水量平衡**：

```
每分钟变化 = 灌溉 + 降雨 − 作物蒸散 − 深层渗漏
```

- **蒸散**（作物蒸发+土壤蒸发）由太阳高度角驱动，所以**白天降得快、夜里几乎不动**，
  正午最强；阴天、气温低时减弱。
- **深层渗漏**：含水量超过「田间持水量」后，多出来的水会往下渗走。沙土渗得快，
  黏土渗得慢——这是三块地表现不同的主要原因。
- **降雨**取自大连的真实天气预报，按当天下雨概率随机生成阵雨；下雨时蒸散也会被压低。
- 三块地的土壤质地、作物系数、灌溉触发点都不一样，所以**三条曲线不会重合**。

### 5.2 你会观察到的正常现象

| 现象 | 说明 |
| --- | --- |
| 夜里的曲线几乎是平的 | 没有日照就几乎没有蒸散，正常 |
| 白天上午到下午一路缓降 | 蒸散最活跃的时段 |
| 某块地突然跳升然后慢慢回落 | 自动灌溉开泵 → 到目标停泵，多余的往下渗 |
| 雨后几块地一起抬升 | 降雨是全场共用的 |
| 同一个数字在 0.1 上下轻微抖动 | 真实传感器的读数噪声，模拟器特意保留了 |

### 5.3 什么情况下才算异常

- **三块地完全一样、且几分钟都不变**：模拟器可能没在推数据，找管理员看
  `journalctl -u moisture-simulator`。
- **数据新鲜度徽章变红**：见 Q2。
- **含水量长期低于 30%**：会触发上游的自动灌溉（阈值 30%），且看板会报警。

> 早期的版本三路恒为 `80.0` 不动，那是旧模拟器的饱和缺陷；已按真实物理模型重写，
> 详见 `DEPLOY.md` 第 9 节。

## 6. 常见问题

### Q1：页面显示「灌溉服务暂时不可达」

**上游**灌溉系统没响应，不是看板坏了。看板会正常显示界面（可能带缓存数据），
不会报错崩掉。

找技术同事确认上游 `irrigation-server` 的状态。**不要自己去重启服务器上的服务。**

### Q2：数据新鲜度徽章变红「数据已过期」

超过 10 分钟没有新数据。先刷新页面；还是红的就找技术同事。

### Q3：三个通道数字为什么不一样 / 为什么在变

见第 5 节——三块地的土壤质地不同，按水量平衡各自演化，这是设计如此。

### Q4：预测精度显示 0.0%

见 4.3——上游那段时间还没攒够可比对的历史点，给的就是 `0.0`。现在新模拟器跑起来后
一般在 5%~7%，会随数据积累变化。看板不编造数字。

### Q4b：累计时长不动了 / 显示橙字「计时已暂停」

说明后端超过 10 秒没拿到新鲜读数（网络抖动、上游服务重启、或者泵刚好停了在交接）。
数字冻结是**故意的**——那段时间我们没观测到泵在转，不能凭空加。

- 泵其实在转，但一直不恢复 → 刷新页面，还是不动就找技术同事
- 变回正常后数字会**从冻结处原地继续**，断流那几分钟不会补回来

### Q4c：累计时长和上游 `/api/irrigation-stats` 的对得上吗

对得上。看板的总时长 = 上游 `total_duration_sec`（已完成事件之和） + 本次正在跑的秒数。
泵一停，本次那几秒会立刻并进「已完成」，所以总数是连续的、不重复也不丢。

### Q5：事件表格是空的

见 4.4——分两种：真没灌过水（正常），或者部署权限没配好（页面会提示「上游历史库不可读」，找管理员按 DEPLOY.md 11.4 修）。

### Q6：登录提示「请先修改初始密码」

你还在用初始密码，必须改掉才能用。这是强制的，改完就正常了。

### Q7：点「控制」里的按钮没反应

- 观察员角色看不到这个页面（正常）
- 操作员点完要过二次确认框才算下发
- 提示「灌溉服务暂时不可达」= 上游没响应，操作没生效

### Q8：密码输对了还说密码不对

- 可能被锁了（连错 5 次锁 10 分钟）
- 可能账号被停用了（提示「账号已停用」）
- 大小写、输入法全角半角检查一下

### Q9：登出后再打开又要登录

登录状态存 12 小时。如果频繁要求登录，可能是浏览器清了本地存储
（无痕模式、清理工具、或者站点数据被删）。

### Q10：导出的 CSV 里时间是数字

CSV 里有一列时间戳是 Unix 秒（10 位整数），在 Excel 里可以按
`(A1/86400)+DATE(1970,1,1)` 之类的公式转换，或者直接用表格软件识别。

## 7. 安全习惯（请遵守）

- **不要把密码写在便签上贴显示器**，也不要发在群里
- 用完公共电脑**记得登出**（右上角）

- 观察员账号够用就别要操作员——**能开泵的权限是会给生产带来实际后果的**
