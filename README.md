# 🌱 数字孪生灌溉系统

**2026年辽宁省工创大赛 · 工程场景数字化赛项参赛项目**

基于数字孪生的智能农业灌溉优化系统 —— 构建「传感器采集 → 数字孪生模型 → 智能决策 → 执行机构控制 → 效果验证」的完整工程闭环。

---

## 📋 项目简介

传统温室灌溉依赖人工经验，存在三大核心问题：

| 问题 | 表现 | 本项目的解决 |
|------|------|--------------|
| **灌溉滞后** | 无法实时掌握土壤水分，作物缺水才发现 | 3 路电容式土壤湿度传感器每 5 秒采集，数字孪生实时映射 |
| **水资源浪费** | 经验灌溉过量/重复 | 湿度阈值自动触发 + 到时自停，按需灌溉 |
| **缺少预测能力** | 只能回答"现在缺不缺水" | 加权回归预测未来 30~180 分钟湿度 + OpenClaw AI 天气感知 |

## ✨ 核心功能

1. **3 路独立灌溉**：3 个花盆各自独立采集、独立预测、独立控制
2. **实时监控**：土壤湿度 5 秒刷新，Unity 数字孪生同步显示（土壤颜色/LED/水流）
3. **智能预测**：加权回归 + 指数平滑预测未来湿度曲线，留一法自评估模型误差
4. **天气感知**：调用 OpenClaw AI 联网查询天气预报，降雨概率修正预测、驱动场景天气
5. **自动/手动双模控制**：自动阈值灌溉 + 手动/定时控制 + 全路控制
6. **数据持久化**：SQLite 落盘，历史曲线/灌溉事件重启不丢
7. **节水统计**：灌溉次数/用水量/节水率自动统计，工程效果可量化验证
8. **断线自愈**：传感器掉线自动回退模拟数据；ESP32 本地自动灌溉兜底（断网也能浇水）

## 🏗️ 系统架构

### 四层架构

```
┌────────────────────────────────────────────────────────────────┐
│                 可视化层 (Unity 3D，动漫低模风格)                  │
│  程序化场景(温室/花盆/设备/天空) · 数据面板 · 预测曲线 · 天气联动    │
└──────────────────────────┬─────────────────────────────────────┘
                           │ HTTP REST API (端口 5000)
┌──────────────────────────▼─────────────────────────────────────┐
│               数字孪生层 (Python Flask 后端)                      │
│  DataHub 数据中枢 · 预测模型 · 自动决策 · SQLite 持久化            │
│  灌溉统计/节水计算 · WeatherProvider(OpenClaw AI)                 │
└───────────┬─────────────────────────────────────────────────────┘
            │ MQTT (端口 1883，主题 farm/device01/#)
┌───────────▼─────────────────────────────────────────────────────┐
│              边缘数据层 (ESP32-WROOM-32)                          │
│  3路土壤湿度采集(ADC1) · 本地自动灌溉兜底 · MQTT 上报/订阅          │
└───────────┬─────────────────────────────────────────────────────┘
            │ GPIO
┌───────────▼─────────────────────────────────────────────────────┐
│              物理实体层 (3 个模拟花盆)                             │
│  电容式土壤湿度传感器×3 · 继电器模块 · 微型潜水泵×3 · 5V电源        │
└─────────────────────────────────────────────────────────────────┘
```

### 完整数据闭环

```
传感器采集(≤5s) → MQTT上报 → 后端接收建模 → 预测+天气融合 → 自动决策
     → MQTT下发控制(≤3s) → 继电器驱动水泵 → 湿度回升 → 效果统计(节水率)
```

## 🎯 关键性能指标 (KPI)

| 指标 | 目标值 | 实现方式 |
|------|--------|----------|
| 数据采集周期 | ≤ 5 秒 | ESP32 定时上报（实测 5s） |
| 系统控制响应时间 | ≤ 3 秒 | MQTT 即时下发 + HTTP 乐观更新 |
| 土壤湿度预测误差 | ≤ 10% | 加权回归 + 指数平滑 + 留一法自评估（`prediction_accuracy_mae_percent` 字段实时报告） |
| 灌溉水量降低 | ≥ 20% | 按需自动灌溉 + 节水率统计接口（对比传统基线） |
| 系统连续运行时间 | ≥ 2 小时 | systemd 守护 + 断线自动降级 |

## 🔌 API 接口（后端已部署）

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/realtime-data` | GET | 3 路实时数据（channels 数组 + 平均值） |
| `/api/historical-data?hours=24` | GET | 3 路历史数据（SQLite 持久化） |
| `/api/prediction?minutes=30` | GET | 3 路湿度预测（加权回归 + 自评估误差 + 天气修正） |
| `/api/control-pump` | POST | 水泵控制（channel 1-3 / all） |
| `/api/system-status` | GET | 系统状态（含历史库与统计摘要） |
| `/api/weather` | GET | 天气感知（OpenClaw AI，可选） |
| `/api/irrigation-stats` | GET | 灌溉统计（次数/用水量/节水率） |

完整契约见 [`docs/系统接口契约v3.md`](docs/系统接口契约v3.md)。

## 🚀 快速开始

### 1. 启动后端

```bash
cd backend
pip install flask flask-cors paho-mqtt
python irrigation_server.py        # 默认 3 路模拟数据 + auto 数据源
```

### 2. 测试 API

```bash
curl http://localhost:5000/api/realtime-data                    # 3 路实时数据
curl http://localhost:5000/api/irrigation-stats                 # 灌溉统计
curl -X POST http://localhost:5000/api/control-pump \
  -H "Content-Type: application/json" \
  -d '{"channel": 2, "action": "start", "duration_minutes": 5}' # 控制花盆2
```

### 3. 运行 Unity 场景

改 `frontend-unity/Assets/Scripts/ApiConfig.cs` 的 `ServerUrl` 后，场景挂 `SceneBuilder` 点 Play（或菜单「数字孪生灌溉 → 一键生成完整场景」）。

### 4. ESP32 烧录

按 `hardware/esp32/README.md`：改 WiFi/MQTT 地址 → 标定湿度传感器 → 烧录。
